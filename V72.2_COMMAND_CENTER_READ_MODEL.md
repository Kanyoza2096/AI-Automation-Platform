# V72.2 — Command Center Backend Read Model & Truth Adapters

## Purpose
Create one workspace-scoped, read-only Command Center read model over existing authoritative KDO planes.

## Guarantees
- Missing upstream truth is `UNKNOWN` / `UNAVAILABLE`, never fabricated.
- Every populated section carries evidence fingerprint, authority source, freshness and confidence.
- Read model cannot grant action authority.
- Consequential commands remain KCPG → Governance → Action Kernel → Durable Outbox → Connector/Provider → Reconciliation.
- No provider calls, connector execution, or second execution engine are introduced.

## Canonical endpoint
`GET /api/v1/command-center/read-model`

The Python route is workspace-bound through the canonical request context. KCPG exposes the same route as the browser-facing BFF boundary and forwards the authenticated workspace context.

## Adapter strategy
V72.2 deliberately separates the truth contract from the adapters. Each adapter consumes an authoritative runtime snapshot. This allows V72.3+ to attach durable business stores without making the Command Center invent facts from UI state or legacy endpoint heuristics.

## Certification status
Offline unit/contract checks pass. This is not live production certification: live database freshness, restart persistence, provider state, and real-time update latency remain environment-dependent evidence.
