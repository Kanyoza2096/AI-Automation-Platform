# V71.13 — Production Runtime Convergence

## Purpose
Make the V70 Business Operating Layer and V71 Governed AI Workforce explicit parts of the production application composition root, without creating a second executor or deleting the existing Kanyoza engines.

## Implemented
- `services/v71_13_production_runtime_convergence.py`
  - verifies V70/V71 layer imports at boot
  - composes workspace-scoped V70 Business Operating Layer and V71 workforce registries
  - composes V71.10 durable runtime and V71.11 observability/control plane
  - preserves the existing BusinessAutomationEngine as the governed business execution dependency
  - explicitly records that live provider certification remains unproven
- `routes/production_runtime_routes.py`
  - authenticated runtime-convergence observability endpoints
- `main.py`
  - installs V71.13 immediately after the production service container is built
  - mounts the convergence observability router
- V70.8 customer lifecycle module/schema restored into this release because the V71.12 source package did not contain the V70.8 implementation even though the V70/V71 roadmap treats it as part of the operating layer.

## Architecture law
V71.13 does **not** replace Meta Engine, Director, Condition Engine, EventBus, AutonomousLoop, Council, DecisionGate, Action Kernel, durable outbox, connectors, or providers wholesale.

It establishes the composition boundary:

`Business Objective -> Business Operating Layer -> Governed AI Workforce -> Governance -> Action Kernel -> Durable Outbox -> Connector -> Provider -> Result -> Reconciliation -> Outcome`

Legacy engines remain available as infrastructure during controlled convergence. They must not become a parallel authority/execution plane.

## Certification status
`NOT_PROVEN`.

V71.13 proves source-level/runtime composition and tenant-scoped construction. It does not prove real provider side effects, production restart persistence, multi-worker race behavior, credential revocation, or provider rate-limit behavior.
