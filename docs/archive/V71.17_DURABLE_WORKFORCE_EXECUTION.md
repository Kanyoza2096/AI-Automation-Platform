# V71.17 — Durable Workforce Execution Convergence

## Purpose
Close the runtime gap between a V71.16 durable workforce proposal and the existing governed execution plane without creating a second executor.

## Canonical path
`AutonomousLoop -> V71 Workforce -> durable run -> V71.17 claim -> V70 catalog workflow -> existing governance -> Action Kernel -> durable outbox -> connector/provider -> reconciliation`

## Safety rules
- A workforce run must have a durable V71.10 lease before execution.
- A run without an explicit governance envelope manifest is blocked; the coordinator never invents authority, approval, or an envelope.
- Workflow resolution is catalog-only via `business_automation_catalog.get_template`.
- The coordinator never calls providers or connectors directly.
- Legacy `AutonomousLoop._handle_publish_command` no longer calls `run_publish`; a bare legacy command is fenced.
- Expired RUNNING leases are reconciled first; they are never blindly reclaimed.
- Execution authority remains the existing Action Kernel/outbox path.

## Production wiring
`main.py` installs the V71.17 coordinator after V71.13–V71.16. The AutonomousLoop receives the coordinator factory so its legacy publish command can only route an existing durable workforce run.

## Important certification boundary
Offline tests prove structural wiring and safety invariants. They do **not** prove live provider execution, restart persistence of all workforce control registries, multi-worker race behavior, credential revocation, or provider rate limits. Those remain deployment/staging certification work.
