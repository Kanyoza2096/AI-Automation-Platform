# C9.5 Production Readiness Gate

## Purpose

C9.5 aggregates the C9 release evidence without converting missing external evidence into a false PASS.

Every control is one of:

- `PASS` — evidence was produced and the control passed.
- `FAIL` — evidence exists and the control failed.
- `NOT_PROVEN` — required real infrastructure/evidence was not supplied.

The release is production-certified only when **all required controls are PASS**.

## Current certification

In the current build, static/repository controls pass. Real PostgreSQL concurrency, live backup/restore, real provider execution, and real Redis recovery remain `NOT_PROVEN` because this environment does not supply those external systems/evidence.

Therefore the current result is intentionally:

`C9.5 = BLOCKED / NOT_PROVEN`

This is not a test failure; it is a deliberate safety property of the release gate.

## Evidence handoff

External certification runners may emit a JSON evidence manifest and provide its path through:

`KDO_C9_EVIDENCE_MANIFEST=/path/to/evidence.json`

The gate accepts a control as PASS only when the manifest contains that control with status `PASS` and non-empty evidence. Boolean environment variables cannot bypass the gate.

## Required external evidence

1. Real PostgreSQL concurrent claim/state-transition certification.
2. Isolated backup restore followed by deterministic verification.
3. Controlled non-production provider execution with authoritative durable/provider receipt.
4. Real Redis lease/recovery certification.

## Final principle

`PASS` means proven. `NOT_PROVEN` means not certified. Neither is silently upgraded by documentation, unit tests, or operator assertion.
