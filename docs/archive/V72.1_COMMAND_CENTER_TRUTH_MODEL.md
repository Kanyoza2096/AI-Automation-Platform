# V72.1 — Business Command Center Truth Model & KCPG API Contract

## Purpose
Define the authoritative read contract for the Business Command Center before UI reconstruction.

## Boundary
Browser → KCPG Gateway → canonical backend truth sources.
The browser never calls internal Python services directly and never receives internal implementation details.

## Canonical objects
- businessHealth
- objectives
- opportunities
- risks
- decisions
- workforce
- operations
- outcomes
- evidence
- governance

Every object is workspace-scoped and carries freshness/provenance metadata. A value is either observed, derived from observed records, or explicitly unavailable; the contract must not manufacture business meaning from missing data.

## Truth envelope
```json
{
  "schema": "CommandCenterTruth/v1",
  "generatedAt": "ISO-8601",
  "workspaceId": "string",
  "dataState": "LIVE|DEGRADED|UNKNOWN",
  "sections": {}
}
```

Each section has:
`state`, `freshness`, `authority`, `sourceKeys`, `evidence`, `confidence`, `data`.

`authority` describes where the fact came from; it does not grant permission to act.

## Action rule
Read truth is separate from command authority. Any consequential command must use the existing KCPG command surface and continue through governance → Action Kernel → durable outbox → connector/provider → reconciliation.

## V72.1 does not build dashboards
It establishes the stable contract that V72.2+ will hydrate and the existing KDO client will render.
