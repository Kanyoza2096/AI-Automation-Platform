# C9.2 — Observability & SLO Proof

## Implemented

- Existing process-local `utils.metrics.MetricsCollector` is now fed by inbound API request tracing.
- Request metrics use Starlette route templates rather than raw URLs, limiting tenant/resource cardinality.
- API request evidence includes request count, 4xx/5xx errors, and rolling p50/p95/p99 latency summaries.
- Existing SLO computation now incorporates API 5xx-rate and API p95-latency targets without creating a second telemetry system.
- Added read-only `/api/v1/observability/workspace/{workspace_id}` surface joining SLOs, metrics, recent decisions, recent outbox state, and traceability identifiers.
- Added compact `/api/v1/observability/health` probe.
- Existing correlation IDs, decision timelines, Action Kernel execution IDs, outbox state, and reconciliation semantics remain the authoritative chain.

## Evidence

- Focused C9.2 + reliability observability tests: **12 passed**.
- Full backend suite: **976 passed, 0 failed, 1 warning** in **18.36s**.
- Release integrity gate: **PASS**.
- Existing warnings: legacy duplicate migration prefixes; Pydantic V1 `@validator` deprecation.

## Operational truth

This is **observability evidence**, not production certification. Metrics are process-local/rolling and the repository still requires real PostgreSQL concurrency, real provider execution, staging runtime, backup/restore, and performance evidence before final production certification.

## Operator questions now supported

| Question | Evidence surface |
|---|---|
| What happened? | recent decisions + timeline |
| Which workspace? | tenant-scoped observability/SLO surface |
| Which decision? | `decision_id` |
| Which action? | Action Kernel / outbox action type |
| Which provider? | execution/provider evidence |
| How long? | request + component timing metrics |
| Where did it fail? | SLO breach, outbox status, execution result |
| Reconciliation debt? | SLO/recovery/outbox uncertainty signals |
| Prove the chain? | `correlation_id` → `decision_id` → `execution_id` → provider object |
