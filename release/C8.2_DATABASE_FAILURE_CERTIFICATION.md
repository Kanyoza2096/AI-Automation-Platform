# C8.2 — Database Failure / Transaction Certification

## Purpose

C8.2 certifies the failure invariants around durable execution state. It does not claim PostgreSQL behavior is proven by an offline simulator.

## Certified offline invariants

1. Crash before transaction work leaves no committed execution state.
2. State written before commit is rolled back rather than becoming phantom success.
3. Commit without a persisted receipt becomes `uncertain` and cannot be blindly retried.
4. An external side effect before durable commit becomes `uncertain` and cannot be blindly retried.
5. Receipt persistence failure after an external side effect remains `uncertain`.
6. Stale execution ownership is reconciled before another worker can execute.

## Evidence

`services/v72_2_database_failure_certification.py` provides a deterministic state-machine harness. `tests/test_c82_database_failure_certification.py` contains behavioral assertions.

## Production-certification boundary

This module is intentionally not a substitute for a real PostgreSQL test. C8 remains `NOT_PROVEN` for database concurrency/failure behavior until a real PostgreSQL instance is supplied and the C8.1 harness can execute against it.
