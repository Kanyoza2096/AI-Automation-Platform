# KDO V69.3–V69.5 — Secure Connection, Capability Discovery & Canonical Mapping

## Purpose
Establish the integration foundation required for real business systems without putting secrets, provider authority, or execution into the control-plane contracts.

## Delivered
- Opaque, tenant-bound `CredentialBinding`; raw credential material is rejected.
- Explicit connection security status and safe-for-discovery gate.
- Credential revocation state without exposing or mutating secret material.
- Capability discovery constrained by the connector declaration.
- Undeclared provider capabilities/events/actions fail closed.
- Tenant-bound canonical event/data mappings.
- Stable event identity required for mapped event payloads.
- Mapping fingerprints for deterministic contract identity.
- No provider calls, approvals, external effects, or secret persistence.

## Architectural boundary
Credentials remain references into the existing secret/authentication boundary. Connector discovery describes capability; it does not grant authority. Outbound execution remains Action Kernel → durable outbox → certified connector. Inbound delivery remains the tenant-bound event gateway/bridge.

## Validation
Focused V69 integration-foundation tests cover credential isolation, revocation, capability escalation, undeclared provider surfaces, stable event identity, and cross-tenant mapping rejection.
