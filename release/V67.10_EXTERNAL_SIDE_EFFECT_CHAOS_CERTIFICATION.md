# V67.10 — External Side-Effect Chaos Certification

## Objective

Prove the boundary between KDO execution truth and an external provider when the
provider may commit a side effect but the worker loses the response.

## Certification invariants

1. A provider rejection before commit produces no remote state.
2. A provider commit followed by response loss is **UNCERTAIN**, never an ordinary
   retryable failure.
3. Reconciliation can discover the remote committed object by the same
   idempotency key.
4. Provider-side idempotency prevents a recovered worker from creating a second
   external object.
5. The execution ledger remains authoritative for KDO execution state.
6. No AI, learning, recovery planner, or business outcome signal can authorize a
   second side effect.

## Delivered

- `services/v67_external_side_effect_sandbox.py`: deterministic provider sandbox
  with provider-side idempotency and reconciliation.
- `tests/reliability/test_v67_10_external_side_effect_chaos.py`: failure-injection
  coverage for success, pre-commit rejection, timeout-after-commit and
  crash-after-commit.
- `scripts/v67_10_external_side_effect_chaos.py`: fail-closed certification
  runner. Offline mode is runnable now; arbitrary live endpoints are rejected.

## Important certification boundary

This release does **not** claim live third-party provider certification. No
approved provider sandbox/credentials were available. The live gate therefore
refuses arbitrary endpoints instead of turning a certification harness into an
uncontrolled side-effect client.

A future provider-specific live adapter must prove, at minimum: documented
idempotency semantics, remote-state reconciliation, safe test tenant/sandbox
isolation, request/response correlation, and controlled worker termination.
