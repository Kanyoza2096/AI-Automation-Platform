# KDO V69.18 — Business Process Orchestration

V69.18 adds a long-running, event-driven business-process state machine over V69.16 workflow execution and V69.17 event transport.

## Boundary

The orchestrator owns process state and transition planning. It does not call providers, hold credentials, grant execution authority, or bypass V69.15 policy / runtime authorization.

## Capabilities

- event-driven state transitions
- long-running human waits
- timers/deadlines
- escalation targets
- correlation and event consumption lineage
- immutable transition history in the reference model
- tenant isolation and fail-closed cross-tenant handling
- durable PostgreSQL schema with RLS

## Safety

A process transition is not a side effect. Actual actions remain execution requests governed by the existing workflow, policy, Action Kernel and connector runtime boundaries.
