# V67.2 — Failure-Injection & Recovery Runtime Certification

## Purpose

V67.2 hardens the autonomous recovery runtime against failures that occur outside the normal Action Kernel result path. It also adds deterministic failure-injection coverage for the execution boundary.

## Critical runtime fix

Previously, `ActionOutboxWorker.process_row()` entered V67 recovery only when `ActionKernel.process_outbox_row()` returned a normal failure/uncertainty result. If the kernel/worker raised an exception before returning a result, the worker finalized the outbox row as `reconciliation_required` and exited without creating V67 exception evidence or a recovery classification.

V67.2 now feeds that worker-level exception into `RecoveryCoordinator` as an explicitly uncertain result.

This is intentionally conservative:

- worker crash/exception is recorded as reconciliation-required;
- V67 classifies it as uncertain external state;
- no blind autonomous retry is released;
- recovery evidence and plan are persisted;
- execution remains behind the Action Kernel and durable outbox.

## Failure modes covered

1. **Provider success followed by receipt persistence failure**
   - result becomes `uncertain`;
   - reconciliation is required;
   - the system does not report success or automatically duplicate the provider call.

2. **Duplicate idempotency delivery**
   - a repeated execution with the same idempotency key replays the authoritative success;
   - provider operation executes once in the in-memory reliability harness.

3. **Worker-level exception outside the normal result path**
   - outbox is finalized as `reconciliation_required`;
   - V67 exception/recovery records are created;
   - no recovery release occurs.

4. **Recovery release race protection**
   - database-side `FOR UPDATE` locking remains authoritative;
   - only matching failed intents can return to `pending`;
   - attempt budget is enforced by the database;
   - exception/intent/workspace lineage must match.

## Authority boundary

V67.2 does not create a new execution authority. Recovery classification remains authority-free. Autonomous recovery can only re-enter the durable Action Outbox, after which the Action Kernel independently validates the action contract, risk, parameters, approval requirements, workspace, and idempotency boundary.

## Result

V67.2 closes the worker-level exception blind spot and adds adversarial reliability coverage. It does **not** constitute V68 production autonomy certification; production certification still requires environment-level failure injection, provider reconciliation tests, deployment/lease behavior validation, and the outstanding broader release blockers.
