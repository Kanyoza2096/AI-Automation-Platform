# KDO V69.11 — Connector Event Runtime Gateway

## Purpose
V69.11 closes the inbound integration trust boundary. External connector events must be authenticated, tenant-bound, declared, mapped, fresh, and replay-fenced before they can enter KDO's canonical event plane.

## Runtime law
The gateway produces a canonical inbound event. It does **not** invoke BusinessAutomation, the Decision Plane, Council, or the Action Kernel. Downstream systems remain responsible for interpretation, policy, authority, and execution.

## Gates
1. Workspace/connection/mapping identity match.
2. Connection is not suspended/revoked and is in an ingress-ready lifecycle state.
3. External event is declared by the connector contract and matches the configured mapping.
4. Authentication evidence verifies the tenant claim and HMAC signature.
5. Stable event identity is present.
6. Event timestamp is within the configured replay window.
7. Durable/process replay fence reserves `(workspace_id, connection_id, event_id)` before admission.
8. External fields are converted through the tenant-bound canonical mapping.

## Production durability
`MemoryReplayFence` is intentionally only a deterministic test/process-local implementation. Production adapters must implement the same interface with a durable tenant-scoped uniqueness fence. KDO's existing Business Automation event receipt machinery can supply that durable persistence boundary.

## Security posture
- Invalid signatures are rejected.
- Cross-tenant claims are rejected.
- Undeclared events are rejected.
- Suspended/revoked connections are rejected.
- Stale/future events are rejected.
- Missing stable event IDs are rejected.
- Duplicate events are rejected before canonical admission.
- No provider credentials are stored or returned by the gateway.
