# V67.3 — Concurrency & Lease Hardening

## Purpose
Close the race where a slow Action Kernel/provider operation can outlive the action-outbox lease and become claimable by a second worker.

## Changes
- ActionOutboxWorker instances now use unique worker identities even within the same process.
- A live outbox lease is renewed periodically while a kernel operation is running.
- Lease renewal is fenced by workspace, intent, status, and lease token.
- Heartbeat failure never grants execution authority; existing Action Kernel and Execution Ledger fencing remain authoritative.
- Recovery release remains atomic on a terminal failed row and cannot reset processing/reconciliation/succeeded rows.

## Safety invariant
At no point does lease renewal authorize an external side effect. It only preserves ownership of an already-claimed outbox row. External execution remains behind the Execution Ledger and Action Kernel.
