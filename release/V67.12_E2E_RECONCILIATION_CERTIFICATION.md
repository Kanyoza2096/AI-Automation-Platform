# V67.12 — End-to-End Reconciliation Certification

## Objective

Certify the complete boundary from KDO execution through an external side effect
and back into authoritative execution/outcome observation when the provider
commits a side effect but the worker loses the response.

## Required invariant

`provider commit + lost response != provider failure`.

The execution result must become `uncertain`; reconciliation must discover the
remote state; replaying the same execution idempotency key must not invoke a
second external side effect; and the V66 execution observation must not claim
business success.

## Scenarios

1. Lost response after provider commit → uncertain → reconcile → no duplicate.
2. Provider rejection before commit → failed → new governed retry intent → one
   successful side effect.

## Hidden defect found and fixed

V67.12 exposed a V66.1 compatibility bug in `build_execution_observation()`:
the function correctly supported object receipts for most fields, but attempted
`.get()` on an object when `provider_object_id` was absent. The accessor was
normalized to safely support both mapping and `ExecutionRecord` inputs. This is
an actual cross-phase integration defect, not a test-only workaround.

## Governance

This release is a deterministic certification harness using the synthetic V67
provider. It does not authorize production execution or certify a third-party
provider. Live certification remains gated on a provider-specific sandbox,
credentials, isolation evidence, and controlled termination capability.

## Result
