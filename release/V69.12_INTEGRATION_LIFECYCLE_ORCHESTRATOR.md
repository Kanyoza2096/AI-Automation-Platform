# KDO V69.12 — Integration Lifecycle Orchestrator

## Purpose

V69.12 composes the V69 integration contracts into one explicit, fail-closed lifecycle. It prevents callers from treating connection, certification, health, or activation records as independent authorization systems.

## Lifecycle

`DISCOVERED → AUTH_REQUIRED → AUTHENTICATED → VALIDATING → CAPABILITIES_DISCOVERED → MAPPING_REQUIRED → CERTIFICATION_REQUIRED → OBSERVE_ONLY → SUGGEST_ENABLED → EXECUTION_ENABLED`

Failure/degradation paths converge through `DEGRADED`, `SUSPENDED`, or `REVOKED`. Execution cannot be reached by skipping states.

## Control-plane guarantees

- Tenant and connection identity are checked on construction and transitions.
- Execution requires the existing certification registry to be active and unexpired.
- Execution requires a certified connector, suggest-enabled predecessor, and required granted capabilities.
- Health drift converges lifecycle state and certification registry state together.
- Credential/identity/tenant-scope failures revoke; API/capability/mapping/provider drift requires re-certification; unavailable providers suspend; degraded providers degrade.
- Snapshots expose eligibility only; they never grant authority.
- No credentials are stored or accepted by this orchestrator.
- No provider side effects are executed.

## Architectural boundary

The orchestrator is a control-plane coordinator, not an authorization or execution authority. Mutating execution remains:

`Decision/Policy/Approval → Action Kernel → durable outbox/ledger → Connector Runtime Gateway → GovernedConnector → provider`

Inbound events remain:

`provider → Connector Event Runtime Gateway → canonical event plane → Business Understanding`

## Verification

Focused V69.12 lifecycle tests cover direct execution bypass, registry gating, activation, revocation convergence, version drift, and cross-tenant construction.
