# V71.10 — Durable Autonomous Workforce Runtime

## Purpose
V71.10 makes autonomous workforce run state durable and worker-safe across process boundaries. It does not create a second governance or execution engine.

## Runtime law
- Identity, permissions, planning, autonomy envelopes, budgets, takeover and coordination remain admission/control inputs.
- Business governance remains authoritative.
- Action Kernel, durable outbox, execution ledger, governed connectors and reconciliation remain the only external side-effect path.
- A lost/expired autonomous-run lease is **not** a retry authorization.
- A stale RUNNING run is fenced into `paused + reconciliation_required` so the authoritative execution ledger/outbox can establish whether a side effect occurred.

## Durable controls
- Atomic database worker claim with lease token.
- Workspace/run ownership fences.
- Lease heartbeat renewal.
- Attempt counter.
- Lease-token finalization fence.
- Durable reconciliation-required marker.
- Fail-closed production behavior when no durable store is available.
- Explicit in-memory mode is available only when intentionally enabled for tests/development.

## Failure semantics
```text
READY
  -> atomic claim
RUNNING
  -> success -> COMPLETED
  -> known application failure -> FAILED
  -> worker loss / expired lease -> PAUSED + RECONCILIATION_REQUIRED
```

An expired lease must never cause a second autonomous provider attempt. Provider-level idempotency and authoritative execution reconciliation remain downstream responsibilities.

## Budget note
V71.6 budget accounting remains the existing bounded budget control. V71.10 does not pretend that its non-atomic legacy usage counter is a reservation ledger. Atomic budget reservation/commit can be introduced only as a dedicated durable control change; autonomous runtime execution never treats a budget as authority.
