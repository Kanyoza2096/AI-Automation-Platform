# V68.4 — Business Workflow Autonomy Admission

V68.4 connects the V68.1 business autonomy envelope to the real declarative business-workflow catalog without creating a second execution plane.

## Boundary

The new `services.business_workflow_autonomy` module is an admission layer only. It:

- checks workspace, envelope lifecycle, declared action, workflow scope, and risk;
- maps `observe` and `suggest` modes to non-executing outcomes;
- allows only bounded low/medium workflows in `execute` mode to enter the existing BusinessAutomationEngine;
- routes high/critical workflows to existing governance/review rather than auto-approving them;
- rejects metadata attempting to introduce direct provider/connector execution.

It does not call providers and does not grant authority, approval, or policy effects.

## Architectural invariant

`BusinessAutonomyEnvelope -> WorkflowAdmission -> BusinessAutomationEngine -> existing governance/Action Kernel/outbox`

There is no parallel provider execution path.

## Certification scope

The focused tests prove:

1. bounded execute-mode workflow admission;
2. observe/suggest non-execution;
3. high-risk review rather than auto-approval;
4. workspace/action/workflow scope fail-closed;
5. admitted work delegates to the existing engine;
6. blocked work never reaches the engine;
7. direct execution metadata is rejected.
