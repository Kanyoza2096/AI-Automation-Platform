# V70.10 — Business Command & Planning Operating System

## Purpose
Provide a governed management planning layer that turns explicit business objectives, capacity, constraints, and evidence into reviewable plans and prioritized work.

## Canonical flow
Business objective → evidence/signals → planning model → capacity/constraint analysis → plan → management review → explicit governed command → BusinessOperatingLayer → Action Kernel → durable execution.

## Authority boundary
V70.10 is advisory by default. It does not call providers, connectors, or the Action Kernel directly. An item becomes executable only when an explicit governed workflow is supplied, and any command is delegated to the existing BusinessOperatingLayer. Planning cannot manufacture authority.

## Safety properties
- Workspace isolation.
- Deterministic plan and item fingerprints.
- Explicit priorities and positive effort/capacity validation.
- Capacity-aware prioritization and visible trade-offs.
- Explicit executable flag plus governed workflow requirement.
- Duplicate command fencing.
- Terminal-plan protection.
- No autonomous plan-to-provider side effect path.

## Persistence
Migration `085_v70_10_business_command_planning.sql` establishes durable plan and command records. Runtime persistence wiring remains part of the final V70 production certification work; this phase does not introduce a second persistence abstraction.
