# V66.5 — Learning → Decision-Input Integration

## Purpose

V66.5 makes promoted learning available to future decision reasoning as a bounded advisory context. It does **not** turn learning into authority.

## Contract

`services/business_learning_decision_context.py` accepts a validated V65 decision input and V66.4 governed learning. Only `promotion_state=promoted` knowledge from the same workspace is projected.

The projection is capped at 10 knowledge items and contains only reusable advisory fields. It explicitly declares:

- `advisory_only=true`
- `authority=none`
- `policy_effect=none`
- `approval_effect=none`
- `execution_effect=none`

## Safety boundary

Learning cannot:

- authorize an action;
- approve an action;
- change policy thresholds;
- alter Action-Kernel contracts;
- bypass DecisionGate or approval requirements;
- directly execute an action.

Action Kernel and policy remain independently authoritative.

## Persistence

`054_v66_5_learning_decision_context.sql` adds a durable, workspace-isolated projection ledger with RLS and a uniqueness constraint per workspace/understanding.
