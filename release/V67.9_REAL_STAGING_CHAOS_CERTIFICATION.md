# V67.9 — Real Staging Chaos Certification

## Purpose

V67.9 is the bridge from deterministic local/multiprocess simulation to evidence
from the actual staging durable control plane.

The runner `scripts/staging_v67_9_chaos.py` exercises the real Supabase RPCs for
an intentionally unsupported probe action. It therefore tests ownership and
lease semantics without invoking a business provider or creating an external
side effect.

## Live gate

The runner is fail-closed. A real run requires:

- `--live`
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `KANYOZA_STAGING_WORKSPACE_ID`

Without `--live`, no network operation occurs.

## Evidence collected

1. Worker A atomically claims the probe.
2. Worker B cannot claim while A's lease is live.
3. A's current lease token can renew.
4. A stale lease token cannot renew.
5. After lease expiry, Worker B can reclaim the row.
6. The probe action is intentionally unsupported, so no provider side effect is
   possible through the normal Action Kernel.
7. The probe row is cleaned up after the experiment.

## Important limitation

This is **real staging control-plane certification**, not yet full provider
chaos certification. It proves the actual database ownership boundary, but it
does not claim that a real external provider call survived a worker kill.

The next gate must use a dedicated provider sandbox/test connector capable of
recording an idempotency key, then kill the worker at controlled points:

`before provider → during provider → after provider before receipt → after receipt`.

Only that experiment can certify end-to-end external side-effect recovery.
