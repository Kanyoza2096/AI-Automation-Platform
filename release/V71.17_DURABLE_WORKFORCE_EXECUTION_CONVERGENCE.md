# V71.17 — Durable Workforce Execution Convergence

## Purpose
V71.17 closes the workforce-to-execution handoff without creating a second executor.
A V71 workforce run receives a deterministic durable execution handoff and correlation
identity. The existing V71.10 lease, V71.9 bounded operations, V70 BusinessAutomation,
Action Kernel, durable outbox/execution ledger, connectors, providers and reconciliation
remain authoritative.

## Canonical path
`V71 workforce run -> durable handoff -> V71.10 lease -> V71.9 governance -> V70 BusinessAutomation -> Action Kernel -> durable outbox/execution ledger -> connector/provider -> reconciliation`

## Safety invariants
- One workspace-scoped handoff per workforce run.
- Deterministic `workforce:{workspace}:{run}` correlation identity.
- Atomic database claim prevents two handoff workers from dispatching the same pending handoff.
- No provider imports or direct provider calls in this layer.
- No new governance or execution authority is introduced.
- Existing Action Kernel idempotency and Execution Ledger remain the side-effect boundary.
- Missing durable persistence is not silently converted to production in-memory execution.
- Action evidence is linked through the same correlation ID when the durable action outbox is available.
- Uncertain execution remains a reconciliation signal; it is not blindly retried.

## Certification
Offline wiring and focused regression tests pass. Live provider execution, restart/crash
persistence, multi-worker races against production infrastructure, credential revocation and
provider rate-limit behavior remain `NOT_PROVEN` until exercised in a real staging/production
environment.
