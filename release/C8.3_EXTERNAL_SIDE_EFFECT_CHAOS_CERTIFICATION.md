# C8.3 — External Side-Effect Chaos Certification

## Purpose

C8.3 certifies the safety invariants at the KDO/external-provider boundary using an isolated deterministic provider sandbox. It does **not** claim a live Facebook, WhatsApp, payment, CRM, or other production provider was exercised.

## Scenarios

1. Timeout after remote commit → `uncertain`, reconcile to the existing provider object, no duplicate.
2. Worker crash after remote commit → recovery observes the same provider object; no duplicate.
3. Provider rejection before commit → terminal `failed`, allowing a new governed retry identity.
4. Concurrent duplicate delivery → two delivery attempts produce one remote object under atomic provider idempotency.
5. Reconciliation before unknown retry → positive provider evidence precedes any business-success interpretation.

## Boundary

The sandbox models provider-side idempotency and reconciliation. Production-provider semantics remain unproven until a controlled integration environment executes the same scenarios against real providers with non-production credentials and explicit test accounts.
