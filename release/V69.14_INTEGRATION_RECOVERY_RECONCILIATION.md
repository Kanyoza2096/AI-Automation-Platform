# KDO V69.14 — Integration Recovery & Reconciliation

## Purpose
V69.14 closes the ambiguous-external-state gap between governed execution and safe recovery.

## Safety contract
- `uncertain` and `partial` external outcomes are never blind-retried.
- Provider-authoritative confirmation is required before an ambiguous intent can be closed or retried.
- Confirmed success closes recovery debt; it does not execute a second mutation.
- Confirmed absence may release a retry only when the original action is safely idempotent and within the bounded retry budget.
- Non-idempotent, irreversible, approval-required, or inconclusive cases remain review/reconciliation work.
- Recovery recommendations carry no authority and never invoke providers.
- Actual execution remains behind the existing Action Kernel / governed connector / durable execution ledger.

## Architecture
`ExecutionLedger -> RecoveryCoordinator -> Provider Reconciler -> RecoveryDecision -> Action Kernel`

V69.13 evidence records each control-plane decision. V69.14 adds a durable recovery-case schema with explicit no-authority/no-execution invariants.

## Certification
Focused V69.14 tests cover ambiguous state, authoritative success, authoritative absence, inconclusive reconciliation, idempotency, irreversible actions, retry budgets, and transient failures.
