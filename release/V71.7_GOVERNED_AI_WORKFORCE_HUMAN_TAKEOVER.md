# V71.7 — Governed AI Workforce: Human Takeover

V71.7 introduces an explicit human-handoff boundary for cases where an AI
worker must stop and obtain human judgment.

## Controls
- tenant-scoped takeover cases bound to active agent identity
- explicit requested → claimed → resolved lifecycle
- terminal replay protection
- only the claiming human may resolve a claimed case
- immutable/tamper-detectable case fingerprints
- structured handoff context for downstream governance
- explicit dispositions: resume to governance, reject, escalate
- pending-case visibility
- no provider, connector, Action Kernel, approval or autonomy-envelope execution

## Architectural invariant
Human takeover is a **control boundary**, not an alternate execution engine.
A human resolution can provide a governance input, but this module does not
execute the resulting action and cannot grant an agent authority. A
`resume_to_governance` disposition means the case may return to KDO's normal
policy/risk/approval/Action Kernel path.

## Why this matters
The workforce must be able to stop safely when confidence, risk, policy,
resource limits or business judgment require a person. The stop must be
explicit, durable in production schema, attributable to a human, replay-safe,
and impossible for the agent itself to silently override.
