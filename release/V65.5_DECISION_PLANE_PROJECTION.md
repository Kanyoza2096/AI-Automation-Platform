# V65.5 — Decision-Plane Projection

## Objective
Create a strict contract between V65 business interpretation and KDO's decision plane.

## Architecture
Customer message → AI/deterministic interpretation → evidence/confidence governance →
V65.4 disagreement resolution → **V65.5 decision input projection** → KDO decision plane →
policy/approval → Action Kernel.

The projection is a derived, side-effect-free contract. It carries business meaning and
trust state, but it cannot carry authorization.

## Contract
`services/business_understanding_decision_input.py` exposes `build_decision_input()` and
`validate_decision_input()`. The projection contains tenant/message/customer context,
selected intent/signals, confidence, governance state, resolution state and disagreement.
Provider/model/raw evidence/rationale are deliberately excluded. `authority` is hard-coded
to `none` and validation rejects any other value.

## Event
WhatsApp emits `business.decision.input.ready` after the canonical understanding is
validated. The event is informational and is not an approval or execution command.

## Automation safety
Business Automation condition evaluation supports bounded dotted dictionary paths such as
`business_decision_input.intent` and `business_decision_input.decision_eligible`. This is
not expression evaluation or executable lookup. Governed sales catalog entries for opt-out,
AI-understanding notification, and adaptive next action now consume the new decision-input
event; consequential actions remain behind existing governance and Action Kernel controls.

## V65.3 correction discovered during V65.5
Deterministic evidence was accepted by the deterministic interpreter but was not copied into
the canonical understanding. That caused supported deterministic interpretations to become
`insufficient_evidence`. V65.5 fixes this by applying the same exact-excerpt verification to
deterministic evidence.
