# KDO V69.1/V69.2 — Business Integration & Operating Onboarding

## Purpose
Establish the first platform-level contracts for connecting a real business to KDO and progressively moving an integration from discovery to governed operation.

## Delivered
- Tenant-bound `BusinessOperatingIdentity`.
- Declarative `ConnectorContract` with explicit capabilities, events, actions, risks and certification state.
- `IntegrationConnection` lifecycle with no credentials or authority embedded in the contract.
- Fail-closed connection state transitions.
- Objective-to-capability readiness that only considers same-workspace connections.
- Read-only onboarding assessment: connect → validation → observe → suggest → operating.
- Migration 066 with tenant-scoped control-plane tables and member SELECT RLS.

## Safety boundary
These contracts do not authenticate, store secrets, approve actions, call providers, or execute external effects. Existing Decision Policy, approval, Action Kernel, durable outbox, execution ledger and reconciliation remain authoritative.

## Validation
Focused V69 tests cover tenant isolation, capability leakage, lifecycle transitions, and onboarding state. Full backend regression should be run from the complete source tree before production certification.
