# V70.1 — Real Business Operating Layer

## Purpose
V70.1 turns the V69 integration/control architecture into a workspace-scoped business operating surface.

It introduces:
- a business operating profile;
- bounded business objectives;
- explicit objective-to-workflow scope;
- advisory operating admission;
- a single governed event execution facade;
- stable event identity and run evidence fingerprints.

## Authority rule
The V70.1 layer does **not** become a second execution engine. It delegates admitted catalog workflows to `BusinessAutomationEngine.run_event()`. Provider execution remains behind the existing governance, Action Kernel, outbox, connector and reconciliation boundaries.

## Safety invariants
- tenant mismatch fails closed;
- inactive operating profiles cannot register objectives;
- unknown workflows cannot enter objectives;
- workflows outside objective scope are rejected;
- missing event IDs are rejected;
- high-impact workflows remain review-required;
- operating admissions contain no authority or execution effect;
- the operating layer exposes no raw provider/connector execution surface;
- database control-plane records enforce `authority_granted=false` and `execution_effect='none'`.

## Production boundary
V70.1 is the first business-operating runtime layer, but it does not claim that KDO can operate every business domain automatically. The catalog and connector capabilities still determine what a workspace can actually operate.

## Next V70 work
Expand the operating layer domain-by-domain: CRM/customer operations, sales, content/marketing, finance/operations, outcome measurement, and business-level dashboards/control surfaces. Each domain must use the same governed execution path rather than creating a parallel executor.
