# KDO V69.10 — Connector Runtime Gateway & Capability Enforcement

## Purpose

V69.10 makes connector certification/activation state a runtime prerequisite for externally mutating operations. The gateway is the tenant-bound choke point between KDO governance and the existing `GovernedConnector` execution adapter.

## Runtime mutation gates

A mutating connector operation is admitted only when all of the following are true:

1. workspace/connection/registry identity matches;
2. registry state is `ACTIVE`;
3. certification evidence exists and is not expired;
4. certification evidence connector version matches the runtime contract version;
5. connection state is `EXECUTION_ENABLED`;
6. connection autonomy mode is `EXECUTE`;
7. requested capability is declared by the connector contract;
8. requested capability is granted to the tenant connection;
9. requested action is declared as an outbound action;
10. the governed adapter is tenant-bound and its provider identity matches the contract.

Any failed gate produces `ConnectorRuntimeBlocked` before the provider mutation is attempted.

## Authority invariant

The gateway does **not** grant authority. It only enforces runtime eligibility. DecisionGate/policy, approval, Action Kernel, durable outbox/execution ledger and reconciliation remain authoritative execution controls.

## Read-only operations

Lookup, health and credential validation are exposed through the gateway without execution authorization. They remain tenant-bound and do not mutate external state.

## Existing connector compatibility

The gateway delegates all mutations to `GovernedConnector`; it does not call raw connector mutation methods. Therefore the existing durable execution ledger/idempotency/uncertainty behavior remains in force.

## Evidence boundary

V69.10 does not claim live provider certification. Provider behavior remains subject to V69.6–V69.9 certification and health evidence.
