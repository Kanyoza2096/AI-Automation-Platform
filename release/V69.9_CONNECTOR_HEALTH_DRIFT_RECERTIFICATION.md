# KDO V69.9 — Connector Health, Drift & Re-Certification Control Plane

## Purpose

V69.9 makes connector certification continuously governable. Health and drift are treated as evidence that can invalidate stale certification before it is reused.

## Control model

`provider/credential observation -> health/drift assessment -> registry downgrade -> re-certification -> explicit re-activation`

The control plane never grants authority. It only determines whether existing certification evidence remains usable.

## Drift classes

- credential revocation
- identity / tenant-scope drift
- provider/API version drift
- connector version drift
- capability drift
- canonical event-mapping drift
- provider-behavior drift

## Fail-closed responses

- credential or identity compromise -> `REVOKED`
- certification/API/capability/mapping/provider behavior drift -> `SUPERSEDED` and re-certification required
- provider unavailable -> `DEGRADED`
- sustained degradation -> remains non-executable until separately recovered
- expired certification -> re-certification required

## Important boundary

Health is not proof of authorization. Certification is not authorization. Activation is not authority. All mutations must still traverse KDO's existing Decision/Policy, Action Kernel, durable outbox/ledger and reconciliation boundaries.

## Provider verification

V69.9 remains provider-neutral. It does not claim live Meta/provider verification without real controlled credentials and provider evidence.
