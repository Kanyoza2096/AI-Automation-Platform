# KDO V69.8 — Connector Activation & Certification Registry

## Purpose

Turn V69.6/V69.7 certification evidence into a governed runtime lifecycle without
turning certification into authority.

## Implemented

- immutable certification evidence model with fingerprint and expiry
- registry lifecycle: registered → certified → active → degraded/expired/revoked/superseded
- explicit version-drift invalidation
- explicit revocation confirmation
- tenant + connection binding on every transition
- activation eligibility evaluation that is read-only and returns `authority_granted=false`
- persistent registry schema with tenant RLS and no credentials
- certification TTL support

## Safety invariant

A registry record never grants permission to mutate an external system. Actual
execution remains dependent on the existing connection state and the governed
DecisionGate/Action Kernel → durable outbox/ledger → connector → reconciliation
path.

## Certification semantics

Offline certification remains distinct from live provider verification. A passing
V69.7 structural result can enter the registry, but `live_provider_verified` remains
false unless real provider evidence has been produced.

## Verification

Focused V69.8 registry tests cover activation, expiry, version drift, cross-tenant
isolation and revocation, using the existing Facebook reference certification.
