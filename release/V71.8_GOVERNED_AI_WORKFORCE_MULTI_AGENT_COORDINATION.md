# V71.8 — Governed AI Workforce: Multi-Agent Coordination

V71.8 introduces a tenant-scoped coordination plane for multiple governed AI
agents to collaborate without creating a second authority or execution plane.

## Controls
- explicit coordinator and target agent identities
- cross-tenant and self-delegation protection
- target-agent capability/permission re-evaluation
- bounded task dependencies with cycle detection
- capability-unavailable vs advisory-only classification
- deterministic, tamper-detectable coordination fingerprints
- terminal replay protection
- coordination context is advisory and carries no authority or execution token
- no provider, connector, Action Kernel, approval, policy, budget mutation or
  execution calls

## Architectural invariant
Delegation is **not permission transfer**. A coordinator may request that a
second agent perform a capability, but the target agent must independently
satisfy KDO identity, permission, scope, policy, risk, budget, approval and
Action Kernel controls before any side effect can occur.

The coordination plane therefore answers only:
> “Can these agents coordinate this bounded piece of work for governance?”

It does not answer:
> “May the business action execute?”

## Failure model
- missing capability is `CAPABILITY_UNAVAILABLE`, never invented
- denied or scope-incompatible capability is `ADVISORY_ONLY`
- inactive/tampered identities block coordination
- terminal coordination cannot be replayed
- completion means coordination bookkeeping completed; it does not assert
  provider/business outcome success
