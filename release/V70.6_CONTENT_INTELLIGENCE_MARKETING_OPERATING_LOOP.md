# V70.6 — Content Intelligence & Marketing Operating Loop

## Purpose
Turn KDO's existing content intelligence and publishing capabilities into a governed
business capability: objective → brief → evidence → content candidate → governance →
canonical publish → verified result.

## Architecture
`Marketing Objective → Content Brief → Content Intelligence → Candidate → Governance → Action Kernel → Durable Outbox → Canonical Publisher → Provider → Reconciliation → Outcome`

V70.6 deliberately does **not** create a second workflow engine, event bus, Action
Kernel, outbox, or publishing implementation.

## Safety invariants
- AI output remains advisory until explicitly admitted.
- Evidence fingerprints travel with content candidates.
- Every live publish request requires an explicit `decision_id`.
- Platform must be authorized by the brief.
- `prepare_publish_request()` never performs provider I/O.
- Publication status changes only through an explicit reconciliation result.
- Workspace identity is carried through objective, brief and candidate records.

## Production follow-up
The reference implementation is in-memory like the existing V70.2/V70.3 operating
services; migration 081 provides the durable schema for wiring the repository layer.
Live provider certification remains a V69.20 external certification concern.
