# KDO V68.8 — Business Capability Execution-Plane Repair

## Purpose
Close the real execution-plane blockers discovered by V68.7 without creating a second execution architecture.

## Changes
- `notify_operator` is now an explicit Action Kernel contract. Business Automation only validates/adapts and delegates to the Kernel; notifier delivery occurs inside the Kernel's governed execution/ledger boundary.
- `generate_workspace_report` is explicitly classified as read-only. It has no external side effect and therefore does not require a provider-side Action Kernel contract.
- `sales_orchestrate` is explicitly classified as a bounded Action-Kernel delegator. It selects one allow-listed action and delegates that action to the existing Kernel; it is not a second provider execution plane.
- V68.7 certification now understands these explicit architectural classifications.

## Safety
- No new direct provider execution path was introduced.
- High/critical workflows remain `review_required` and still require approval.
- Certification remains non-executing and authority-free.
- No live provider certification was performed.

## Verification

- Full backend suite: 597 passed, 2 known pre-existing source-tree failures, 1 existing Pydantic deprecation warning.

  - `/mnt/data/kdo67_14/kdo19/core/event_api.py`

## Architectural result
V68.7's structural BLOCKED capability set is now empty. The business workflow catalog is structurally wired to the actual runtime execution planes, while read-only and orchestration capabilities are explicitly classified instead of being forced into a misleading provider-contract model.
