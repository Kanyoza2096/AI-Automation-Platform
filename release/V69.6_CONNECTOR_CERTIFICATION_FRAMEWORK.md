# KDO V69.6 — Connector Certification Framework

## Purpose
V69.6 establishes a substantive certification gate before a business integration can be promoted from observation/suggestion into governed execution.

The framework is deliberately offline/control-plane first. It does **not** contact providers, handle raw credentials, grant authority, or execute mutations.

## Certification dimensions

1. **Tenant isolation** — workspace and connection identities must agree; connector contracts must remain tenant-scoped.
2. **Capability honesty** — an adapter cannot expose capabilities/events/actions outside its declared connector contract.
3. **Authentication identity semantics** — credential bindings remain opaque and tenant/connection-bound; KDO authority is not derived from provider authentication.
4. **Idempotency / ambiguous side effects** — KDO application idempotency is not confused with provider-native idempotency. Ambiguous mutations require authoritative lookup/reconciliation or explicitly proven safe retry semantics.
5. **Reconciliation** — connector contracts must acknowledge the need to resolve uncertain provider state.
6. **Rate-limit dependency** — rate limiting must be explicitly represented rather than silently assumed.
7. **Revocation** — inactive credential bindings fail certification; revalidation may be proven by an adapter hook or remain explicit evidence debt when the V69.3 lifecycle owns revocation.
8. **Version compatibility** — a target contract version can be checked before promotion.
9. **Governed execution** — a certified adapter must be presented behind the governed execution boundary; certification itself grants no authority.
10. **Live-provider evidence** — provider behavior is explicitly reported as `NOT_PROVEN` when no live certification was performed.

## New implementation

- `services/v69_connector_certification.py`
- `tests/test_v69_connector_certification.py`

The result contract exposes:

- `CertificationStatus`: `PASS`, `FAIL`, `NOT_PROVEN`
- typed `CertificationFailure` classes
- per-check evidence
- aggregate failure classes
- `live_provider_verified` flag
- immutable certification version `v69.6`

## Safety property

The critical promotion rule remains:

> **Certification proves connector suitability; it does not authorize execution.**

Execution still requires the existing connection lifecycle, policy/approval, Action Kernel, durable outbox/execution ledger, connector adapter, and reconciliation path.

## Provider certification status

No real provider was contacted by V69.6. Therefore this release does **not** claim that Facebook, Instagram, LinkedIn, X/Twitter, Telegram, WhatsApp, or another external provider is production-certified. Live certification is a subsequent evidence-gathering phase requiring controlled credentials and provider-specific test fixtures.

## Database

No migration is required. V69.6 is a certification contract and gate; durable certification history can be added later once the result schema is stable.
