# V71.18 — Workforce Control-Plane Persistence & Restart Convergence

V71.18 rehydrates the existing V71 identity, permission, memory, planning,
evaluation, budget, takeover, coordination, and autonomous-run registries from
their authoritative durable tables before a workspace runtime is admitted.

## Safety law

Persistence restores state. It does not grant authority, approve actions, call
providers, create a second executor, or bypass the existing governance/Action
Kernel path.

## Restart path

DB → control-plane hydration → fingerprint/tenant verification → V71.9 run
state → V71.10 durable lease → V71.17 execution handoff → existing governance →
Action Kernel → durable outbox → connector/provider → reconciliation.

A production workspace fails closed when durable control-plane storage is absent
or when any restored object fails integrity verification.

## Certification

Offline restart-hydration tests are covered. Real production restart/crash
recovery, multi-worker races, credential revocation, provider rate limits, and
live provider side effects remain NOT_PROVEN until exercised in real staging or
production infrastructure.
