# V72.6 — Recommendation Lifecycle + Outcome Feedback

V72.6 turns V72.5 recommendations from request-time intelligence into a durable,
traceable evidence ledger.

## Runtime contract

```text
V72.4 durable truth
  -> V72.5 intelligence
  -> V72.6 materializer
  -> durable recommendation ledger
  -> human lifecycle feedback / outcome attachment
  -> V66 measured outcomes
```

The materializer is idempotent. GET requests never create or mutate recommendations.
Lifecycle events are append-only evidence records. Outcome links are references to
measured business outcomes, not proof of causality by themselves.

## Lifecycle

`ACTIVE -> ACKNOWLEDGED | DISMISSED | SUPERSEDED`

`ACKNOWLEDGED` and `DISMISSED` may only move to `SUPERSEDED`. Terminal state cannot
be silently reopened. Every transition is tenant-scoped, actor-attributed and
fingerprinted.

## Safety

- No provider calls.
- No Action Kernel invocation.
- No outbox writes.
- No governance approval.
- No authority grant.
- Cross-tenant lookup is rejected.
- Duplicate outcome attachments are idempotent.
- Recommendation state never becomes an execution decision.

## Materialization

A worker or application lifecycle may call
`RecommendationLifecycleService.materialize(surface)` after V72.5 generates a
surface. This intentionally is not performed by the cockpit GET endpoint.

## Cockpit

KCPG exposes the durable ledger at:
`GET /api/v1/business-command-center/intelligence/recommendations`
which delegates to the canonical Python read surface. The existing System Command
Center route remains `/api/v1/command-center/situation` and is not replaced.
