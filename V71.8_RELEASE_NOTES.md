# V71.8 Release Notes

## Multi-Agent Coordination

V71.8 adds a governed, tenant-scoped coordination plane for collaboration
between AI agents.

### Proven controls
- coordinator and target agents must both be active and integrity-valid
- self-delegation and cross-tenant construction are rejected
- target capability permissions are independently re-evaluated
- unavailable capabilities are never invented
- denied/scope-incompatible work remains advisory
- task dependency graphs reject missing dependencies, self-dependencies and cycles
- coordination records are deterministically fingerprinted and tamper-detectable
- terminal coordination cannot be replayed
- coordination context explicitly exposes `authority_granted=false` and
  `execution_requested=false`
- the module performs no provider, connector, Action Kernel, approval, policy,
  budget mutation, or external side effect

### Test evidence
- V71.1–V71.8 focused suite: 41 passed, 0 failed
- full repository suite: 842 passed, 8 failed
- the 8 full-suite failures are pre-existing repository/environment issues and
  are not V71.8 regressions: two missing external source paths and six legacy
  V68 capability-certification expectations around `notify_operator` risk
  alignment.

### Important boundary
`ACCEPTED_FOR_GOVERNANCE` means only that the target agent currently has the
identity/capability permission needed to take the request into KDO governance.
It is not execution approval and does not reserve budget or authorize a side
 effect. The canonical KDO governance → Action Kernel → outbox → connector
path remains authoritative.
