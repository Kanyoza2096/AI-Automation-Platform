# V71.14 — Production Route/Event Wiring

## Purpose

V71.14 converges production business-event admission onto a single observable facade without creating a second execution or governance plane.

## Canonical path

`ingress route/webhook -> UnifiedEventBus -> BusinessAutomationEventBridge -> V71.14 canonical event router -> BusinessAutomationEngine -> existing governance -> Action Kernel -> durable outbox -> connector/provider -> reconciliation`

Objective-scoped business workflows remain available through the V70 Business Operating Layer. V71.14 deliberately does not invent an objective/workflow mapping for generic events.

## V69 coverage

V69 remains foundational rather than being replaced. The runtime binding explicitly recognizes:

- V69 connector runtime gateway / activation and certification state
- V69 connector event ingress and reconciliation
- V69 business event fabric
- V69 governed workflow execution
- V69 integration policy/lifecycle/evidence
- durable execution/outbox infrastructure used by the existing Action Kernel path

The phase does not instantiate duplicate V69 services merely for visibility; it verifies and documents their position in the canonical dependency graph.

## Legacy runtime

Meta Engine, Director, ConditionEngine and AutonomousLoop remain preserved. The legacy AutonomousLoop is explicitly non-canonical for consequential business execution and must not become an independent authority/executor.

## Production route surface

`GET /api/v1/runtime/route-event-wiring` reports the active binding map and a deterministic binding fingerprint.

## Evidence

Focused regression suite: **31 passed, 0 failed**.

This is a wiring/convergence milestone, not live-provider certification. Live side effects, production restart persistence, multi-worker races, provider rate limits, and credential revocation remain certification gates.
