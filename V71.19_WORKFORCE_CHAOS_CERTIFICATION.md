# V71.19 — Workforce Chaos & Recovery Certification

## Purpose
V71.19 is an offline certification harness for the V71 durable workforce runtime. It deliberately models failure at the boundaries where duplicate execution, stale authority, or unsafe recovery could occur.

## Scenarios
1. Concurrent worker claims — one run has one active lease owner.
2. Crash before external side effect — recovery does not imply a blind retry.
3. Crash after external side effect — ambiguous outcome is fenced for reconciliation.
4. Lease expiry — running work becomes reconciliation-required rather than directly reclaimable.
5. Restart hydration — durable run identity and lease metadata survive process reconstruction.
6. Permission change — recovered execution requires fresh permission evaluation.
7. Budget exhaustion — autonomous continuation is blocked when budget is exhausted.
8. Human takeover — active takeover fences autonomous continuation.
9. Duplicate event — stable tenant-scoped event identity is admitted once.
10. Tenant isolation — a run cannot be claimed through another workspace.

## Certification result
The offline harness currently passes all 10 scenarios. This proves modeled invariants only; it does not prove provider behavior, production database failover, or real network/process crashes.

## Execution authority
The certification harness never invokes a provider, connector, Action Kernel, or external side effect. It is evidence generation only.

## Remaining live evidence
A controlled staging exercise is still required for:
- actual worker/process crash and restart;
- two real workers racing against the same durable row;
- provider-side ambiguous outcomes;
- credential revocation during execution;
- provider rate limiting;
- durable database failover/recovery.
